# 稳定性加固 QA 计划

## 进入条件

- 图片、目录、识别和原生相机修复完成。
- 测试不接触真实用户照片、API Key 或第三方计费接口。
- 所有生产签名材料仅通过 CI Secrets 提供。

## 执行阶段

1. 组件测试：图片存储、统一目录、网络仓储。
2. 集成测试：AppController 导入、迁移、恢复和并发状态机。
3. 结构检查：格式化、静态分析、关键路径覆盖率。
4. 平台检查：Kotlin 编译、debug APK、正式签名 release APK。
5. 真机回归：快速连拍、失败恢复、进程强杀、版本升级。

## 退出条件

- 自动化用例 100% 通过。
- Critical/High 风险全部有实现和测试证据。
- debug 与 release 构建通过。
- 真机回归无阻断缺陷。
- 发布标签版本与 `pubspec.yaml` 一致。

## 失败处理

- 自动化或构建失败：停止发布，修复后全量重跑。
- 真机出现重复文件、OOM、数据丢失或队列卡死：按 Critical 处理。
- 签名 Secrets 缺失或版本不匹配：CI 必须失败，不允许回退 debug 签名。

## 当前结果

- `flutter analyze`：通过，0 问题。
- `flutter test --coverage`：21/21 通过。
- 行覆盖率：整体 51.1%；图片存储 84.6%，统一目录 87.9%，设置仓储 53.2%，识别仓储 62.1%，AppController 53.4%。
- Android debug APK：构建通过。
- Android release split APK：使用一次性 QA keystore 构建通过，armeabi-v7a、arm64-v8a、x86_64 三个产物均通过 APK v2 签名校验。
- Android 无签名材料的 release：按预期失败，没有回退到 debug 签名。
- iOS Simulator：构建通过；iPhone 16 与 iPhone 16 Pro / iOS 18.4 安装启动正常，未发现 Flutter 异常；日志中仅有模拟器框架自身的缓存、焦点和启动统计告警。
