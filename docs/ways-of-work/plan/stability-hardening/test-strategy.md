# 稳定性加固测试策略

## 范围与质量目标

本轮覆盖图片导入与去重、临时缓存清理、旧图片迁移、目录持久化、识别队列恢复、网络超时、Android 原生相机和发布签名。质量目标如下：

- 相同图片重复或并发导入时只保留一个永久文件和一个队列项目。
- 旧版本原图在启动优化后压缩、去重，遗留临时图可统计且可清理。
- 任意目录写入失败不会把未保存状态留在内存中。
- 主目录文件损坏后可从最后一次已校验备份恢复。
- 进程中断遗留的 `processing` 项会重新进入 `queued`。
- 火山识别同时请求不超过 4 个，单个请求不会无限等待。
- Android debug、正式签名 release 构建均可通过；未配置签名时拒绝生成 release。

## 风险与优先级

| 风险 | 严重度 | 验证方式 |
| --- | --- | --- |
| 原图与缓存重复导致 GB 级膨胀 | Critical | 单元测试、迁移测试、缓存统计 |
| 多张高像素图同时解码导致 OOM | Critical | Isolate 边界测试、并发导入测试、构建验证 |
| 识别任务崩溃后永久卡住 | Critical | 状态迁移测试 |
| 双 JSON 写入中断导致数据丢失 | Critical | 原子目录、备份恢复、失败回滚测试 |
| 网络请求永久阻塞整个队列 | High | 超时测试、并发上限测试 |
| release 签名变化导致无法升级 | Critical | CI 配置审查、临时正式签名构建 |
| 相机失败后快门永久锁死 | High | Kotlin 分支审查、Android 编译、真机回归清单 |

## ISTQB 测试设计

- 等价类：首次图片、重复图片、旧版图片、损坏图片、缺失图片。
- 边界值：2048px 缩放边界、1 小时缓存保留边界、4 个并发边界、2MB 响应边界。
- 状态迁移：`queued → processing → ready/failed`，以及重启后的 `processing → queued`。
- 决策表：主目录/备份/旧文件存在、缺失或损坏的组合。
- 经验法：存储写满、进程被杀、网络不返回、快速连拍、重复事件回传。

## ISO 25010 覆盖

- 功能适合性：图片、目录和识别结果保持一一对应。
- 性能效率：后台压缩、缩略图按显示尺寸解码、识别并发受限。
- 可靠性：原子写入、备份恢复、状态恢复和超时。
- 安全性：远程端点强制 HTTPS，API Key 继续存入安全存储。
- 可维护性：目录仓储和存储服务可注入临时目录并独立测试。
- 可移植性：Flutter 静态分析、Android debug/release 构建。

## 环境与测试数据

- Flutter VM 单元/集成测试使用系统临时目录，不读取真实用户数据。
- 图片使用运行时生成的 JPEG，包含 64px、640px 和 3000px 尺寸。
- 网络测试使用本机回环 `HttpServer`，不向外部服务发送请求。
- Android release QA 使用一次性临时 keystore；生产发布必须使用 GitHub Secrets 中的固定 keystore。
- iOS 冒烟使用 iPhone 16 与 iPhone 16 Pro / iOS 18.4 Simulator；相机行为仍必须由真机验证。

## 质量门

进入发布候选前必须满足：

- `flutter analyze` 无错误和警告。
- 全部自动化测试通过，关键高风险场景 100% 有用例。
- Android debug APK 和带签名 release APK 均构建成功。
- 没有 Critical/High 未解决缺陷。
- 真机相机回归清单完成后才可对外发布。
